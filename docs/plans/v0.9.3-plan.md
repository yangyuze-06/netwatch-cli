# netwatch-cli V0.9.3 Plan

## 目标

V0.9.3 只修路由器设备发现交互、文案、能力边界和错误提示。

不新增漏洞扫描功能，不抓取路由器密码，不绕过登录，不爆破，不读取浏览器 Cookie，不实现 GSWIFI 私有接口逆向。

## 背景

真实环境中用户打开的后台是：

```text
http://192.168.1.1/cgi-bin/luci/admin/bandwidth
```

页面品牌显示为 GSWIFI，属于 LuCI / OpenWrt / 厂商定制后台风格。页面里能看到设备列表，但 URL 没有小米/Redmi 常见的 `;stok=`。

旧交互把路由器同步入口默认描述成“小米路由器后台”，并在普通 LuCI URL 上只提示“未能提取 ;stok= token”，容易让用户误以为所有路由器都应该有 stok。

## 实现范围

- 局域网设备发现菜单文案改为“路由器设备名同步（实验）”。
- 同步入口先选择方式：
  1. 小米/Redmi stok API。
  2. 通用 LuCI/OpenWrt 后台（暂不支持自动同步，仅说明）。
  3. 返回。
- 选择小米/Redmi stok API 时保留现有 `;stok=` 提取和只读 devicelist API。
- 选择通用 LuCI/OpenWrt 后台时只显示能力边界说明，不要求粘贴 stok URL，不调用小米 API。
- 没有 `;stok=` 时输出更清楚的错误：
  - 未检测到 `;stok=`。
  - 该方式仅适用于小米/Redmi 登录后的 URL。
  - 当前 URL 可能是普通 LuCI/OpenWrt/厂商后台。
  - 建议选择通用 LuCI/OpenWrt 说明入口，或使用快速扫描。

## 能力边界

- 路由器管理后台打开是通用功能。
- 自动设备名同步目前仅支持小米/Redmi stok API。
- GSWIFI / OpenWrt / LuCI / 其他厂商后台可能没有 `;stok=`。
- `netwatch-cli` 当前不读取浏览器 Cookie。
- 不绕过登录。
- 不逆向厂商后台私有接口。
- 对于非小米路由器，请使用 Ping + ARP 设备发现。
- 未来可以为具体品牌/型号增加只读适配器。

## 测试要求

- 普通 LuCI URL 缺少 `;stok=` 时输出清晰说明。
- 通用 LuCI/OpenWrt 选项只显示说明，不调用小米 API。
- 小米/Redmi stok URL 仍可正常提取。
- 所有 router API 调用必须 mock，不真实请求路由器后台。
